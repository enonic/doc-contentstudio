= Reset
:toc: right
:experimental:

The *Reset* action restores inheritance for a localized item in the current <<../projects/layering#,layer>>. It replaces local values with the corresponding parent item's current values and makes the content form read-only again.

== Availability

Reset is available in the <<../editor#,Content Editor>> after an item's content data has been <<localize#,localized>>. Use <<edit#,Edit>> to open the item, then click btn:[Reset] in the editor toolbar. The action applies to the item open in that tab and requires permission to modify it in the current layer.

Content created directly in the current layer has no inherited parent item to reset to.

== Effect on the item

Reset restores every inheritance dimension that was made local. In addition to replacing edited content data, it can replace a local path name, location, or child sort order. See <<../projects/layering#content_inheritance,Content inheritance>> for the four dimensions and their propagation rules.

The item resumes receiving changes from its parent according to those rules. Reset affects the current layer's item; it does not change the parent item.

IMPORTANT: Reset discards the item's current local adaptations. It uses the parent's current values, which may differ from the values the item had when it was first localized. The reset action cannot be undone directly.

Earlier local versions remain available in <<../contextpanel/version-history#,Version history>>. That panel describes how to inspect previous values and when a content version can be restored.

== Working after reset

The inherited content form is read-only. To adapt its values locally again, use <<localize#,Localize>> in the Content Editor.

Reset updates the layer's draft without publishing it. Review the result and use the normal <<../workflow#,workflow>> to publish any changes that should go live. Each layer maintains its own publishing state; see <<../projects/layering#_publishing_and_versions,Publishing and versions>>.
