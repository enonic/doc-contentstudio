This page covers marking content ready and publishing its draft. To take published content offline, see <<unpublish#,Unpublish>>. For review requests and editorial tasks, see <<../workflow/issues#,Issues>>.

[[mark_as_ready]]
== Mark as ready

Use *Mark as ready* in the Content Editor or Content Navigator to mark valid, in-progress content as ready for publishing. The action is disabled for invalid content. After marking, the Publishing wizard opens automatically; marking an item ready does not itself publish it.

The toolbar then offers *Publish* or *Request publishing*, depending on your permissions. Editing the item again returns it to *In progress*. See <<../workflow#_ready_for_publishing,Ready for publishing>> for workflow states and indicators, and <<#_validation,Publishing validation>> for marking items ready within a publishing batch.

[[publish]]
== Publish

Publishing makes the current draft of an item available online, subject to its <<../workbench/permissions#,permissions>>. New content must be published before it is available to end users, and changes to online content must be published again to go live.

Before an item can be published, it must be valid and marked as ready. Users with editing and publishing permissions can also publish in-progress content directly from the editor; see <<#_publishing_from_the_content_editor,Publishing from the Content Editor>>.

Open the *Publishing Wizard* using:

* *Publish* in the toolbar or its menu.
* *Publish* in an item's right-click menu in the Navigator.
* `⌘ + alt + p` on macOS or `Ctrl + Alt + P` on Windows/Linux.

The toolbar's default action depends on the selection's state and your permissions. Its menu also provides related <<../actions#,content actions>>, including <<#publish_tree,Publish tree>>, <<unpublish#,Unpublish>>, and <<../workflow/issues#publish_requests,Request publishing>>. Use a publish request when another user needs to review or publish the content.

=== Draft and Master branches

Content is created and edited in the *draft* branch. Saving creates a new version without changing what is online. Publishing copies the active draft version into the *master* branch, making that version available outside Content Studio according to its permissions.

After publishing, further edits remain in draft until published again. Each project or layer has its own draft and master branches. See <<../workflow#,Content life cycle and workflow>> for the workflow and publishing states, and <<../projects/layering#_publishing_and_versions,Publishing and versions>> for layers.

=== Change status

Each item in the wizard shows its current publish state and change status, such as *Online | Modified* or *Offline | New*. An online item can have unpublished changes; publishing it updates the version that is already live. Items with no changes to publish are not included in the publishing batch.

See <<../workflow#change_status,Change status>> for the meanings of New, Modified, Moved, Published, and Unpublished. To remove content from the active tree and take it offline, use <<delete#delete,Delete>>; archived items can be restored or permanently deleted from the <<../workbench/archive#,Archive>>.

[[publishing_wizard]]
=== Publishing wizard

The wizard lists the selected items, their dependencies, and any conditions that block publishing. Review the included content before confirming. When all checks pass, the status bar displays *Content is ready for publishing* and btn:[Publish now] becomes available. For a batch with multiple items, the button shows the number of items to publish.

.Publishing wizard with an online item whose location has changed and an optional dependency left unchecked
image::publish.png["Publishing Wizard showing a ready item, Include child items, an unchecked dependency, Add comment, and Publish now", 900]

The selected items appear above the *Dependencies* list. Click an item's name to open it in the Content Editor. The remove control beside a selected item removes it from this publishing batch when allowed; it does not delete the content.

==== Dependencies

Publishing can involve more than the original selection. The wizard resolves related content and includes required dependencies, such as ancestors needed to preserve the content tree. By default, optional dependencies are listed but left unchecked. Select the ones whose changes should be published with the selected content.

* *Include child items* adds an item's descendants to the batch. This checkbox appears beneath selected items with children that have unpublished changes.
* The checkbox beside a dependency includes or excludes that item. *All* selects or clears the dependencies that can be changed together.
* Required items have disabled controls. An ancestor may be required because a child is included; exclude the child and apply the change before trying to exclude that ancestor.

.Optional dependencies can be selected individually
image::publish-dependencies.png["Dependencies list with one of three items selected and a Hide excluded control", 830]

Changing the selection displays a blue status bar. Click btn:[Apply] to confirm the selection and recalculate dependencies and validation, or btn:[Cancel] to discard the pending selection changes. Applying the selection does not publish content.

.Applying a change to Include child items
image::publish-apply.png["Include child items selected with Apply and Cancel controls in the status bar", 820]

Use *Hide excluded* to show only included dependencies. *Show excluded* reveals unchecked items again so they can be added back. This changes the list's visibility, not which items will be published.

.Excluded dependencies hidden from the list
image::publish-hide-excluded.png["Dependencies list showing only the selected item with a Show excluded control", 830]

TIP: Administrators can configure optional dependencies to be selected automatically. See <<../config#exclude_optional_dependencies,Exclude optional dependencies>> for the setting.

==== Validation

The wizard checks the included items before allowing publishing. Separate status bars identify *In progress* items, *Invalid items*, and items for which the user lacks publish permission. Publishing remains disabled while blocking conditions remain.

.In-progress and invalid items block publishing
image::publish-blocking.png["Publishing Wizard with separate In progress and Invalid items warnings, Exclude controls, and disabled publishing buttons", 880]

Each warning offers applicable actions:

* btn:[Mark as ready] marks the in-progress items ready together. It does not fix invalid content.
* btn:[Exclude] removes the affected items from the publishing batch when they are optional. Required items cannot be excluded.
* Click an item's name to open it in the Content Editor, complete or correct its content, and mark it ready individually. The wizard updates its checks when the content changes.

.A single in-progress item must be marked ready before publishing
image::publish-in-progress.png["Publishing Wizard with an In progress warning and Mark as ready button for a single item", 900]

Once all checks pass, the green ready message replaces the warnings and publishing becomes available. For validation rules and workflow states, see <<../workflow#_invalid,Invalid content>> and <<../workflow#_in_progress,In progress>>. If another user must publish the content, use <<../workflow/issues#publish_requests,Request publishing>>.

NOTE: The bulk btn:[Mark as ready] action can be disabled through <<../config#disable_mark_as_ready,Content Studio configuration>>. In that case, open and mark each item ready individually.

[[publishing_comment]]
==== Publishing comment

Click btn:[Add comment] to enter an optional comment for the publication. The comment is recorded in the content's <<../contextpanel/version-history#,Version history>>, where it provides context for the published changes. Use btn:[Remove comment] to discard it before publishing.

.Adding a comment to the publication
image::publish-comment.png["Publishing Wizard with a Comment field and Remove comment button", 900]

[[scheduled_publishing]]
=== Scheduled publishing

When the batch includes content that can be scheduled, btn:[Schedule] appears beside btn:[Publish now]. It opens the scheduling fields below the content list:

* *Online from* sets when the content becomes available. The default *Now* publishes immediately; enter a future date and time to delay publication.
* *Online to* optionally sets when the content is taken offline. This must be later than the start time and in the future.

Click btn:[Confirm schedule] to submit the schedule. Use btn:[Cancel schedule] to leave scheduling mode and return to the btn:[Publish now] controls.

.Scheduling fields and confirmation controls
image::publish-schedule.png["Publishing Wizard with Online from and Online to fields, Cancel schedule, and Confirm schedule", 900]

NOTE: Only currently-offline items are scheduled. Other changes included in the batch are published immediately.

The default time and whether an explicit *Online from* value is required can be configured. See <<../config#_default_online_from_time,Default Online from time>> and <<../config#_required_online_from,Required Online from>>. Scheduled and expired items are described under <<../workflow#publish_state,Publish state>>.

[[_publishing_from_the_content_editor]]
=== Publishing from the Content Editor

When *Publish* is invoked from inside the Content Editor, only the currently open item is initially selected. Review its children and dependencies in the wizard just as when publishing from the Navigator.

TIP: Users with editing and publishing permissions can publish content that is still *In progress* from the editor. This automatically marks it ready; the content must still pass validation.

[[publish_tree]]
== Publish tree

*Publish tree* opens the same wizard as *Publish*, with the selection and its descendants included. The wizard also resolves their dependencies. Review the batch, resolve any blocking conditions, and publish or schedule it using the same controls. This is useful when bringing a whole section of the content tree online at once.
