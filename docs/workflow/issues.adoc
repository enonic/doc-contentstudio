= Issues
:toc: right
:imagesdir: images

There are two types of issues in Content Studio: *tasks* and *publish requests*. Both are lightweight work items with assignees, comments, and an Open/Closed state — the *Open Issues* dialog lists both together on separate tabs.

*<<#tasks,Tasks>>* are general editorial work items — "spellcheck this article", "add new content to this section". They carry no workflow meaning: attaching content to a task does not affect the item's <<../workflow#,workflow or publish state>>.

*<<#publish_requests,Publish requests>>* ask another user to review and publish content. They are the standard path for an editor who lacks publish permission, and are also useful when the editor has permission but wants a reviewer to sign off before content goes live.

[[issues_list]]
== Issues list

"*Open Issues"* button in the Content Studio header opens the modal dialog with the list of issues (both tasks and publish requests).
If there are no active issues, the button will say "*No Open Issues*".

image::issues-header.png[Issues button, 478]

The list by default shows all active issues. Use Open/Closed toggler to switch between Open and Closed issues.

image::issues-list.png[Issues list, 719]

TIP: Tasks and Publish Requests are using different icons to make it easier to distinguish them.

By using the filter above the list you can narrow down the list to issues assigned to current user, created by current user,
only Publish Requests or only task. By default, if you have any active issues assigned to you, the filter will be preset to show you only them.

image::issues-list-filter.png[Filter in the Issues list, 716]

To create a new task, click the <<#create_a_task,`New Task…`>> button.

Clicking on an issue from the list will open the <<#update_an_issue,issue details dialog>>.

[[tasks]]
== Tasks

[[create_a_task]]
=== Create a task

To create a new task, click "Create Task..." button in the Content Studio toolbar.

image::create-task-1.png[Create Task, 372]

If some content items are selected in the Content Navigator, you can expand the toolbar menu and select either "Create Task..." or "Request Publishing...".
In this case selected items will be automatically added to a new issue you are about to create.

image::create-task-2.png[Create Task, 372]

You can assign multiple users to work on an issue, using the *Assignees* selector, but you can't assign yourself.

To add specific content to an issue, click on the `Add items` button. The *Items* selector will appear.

image::dialog-issue-1.png[New task, 708]

[[update_an_issue]]
=== Update an issue

To modify an issue, click on it in the <<#issues_list,*Issue list*>> dialog. It will open the dialog with three tabs.

Click the title to edit it, then click anywhere outside of the text field to save the changes.

Under the title you will see the status of the current issue. It can be `Open` or `Close`. Click this button to change the issue status.
Altenatively, you can use `Close Task` button (for an active issue) or `Reopen Task` (for a closed issue).

image::dialog-issue-edit-1.png[Issue title and comments, 714]

==== Comments

The first tab shows comments on the current issue. Comments can be added by clicking the `Comment` button.

TIP: When you are in the comment field, "Close Task" button changes to "Comment & Close Task" to comment and close with one click.

To *edit* or *delete* a comment, click on the *kebab* icon to the right of the comment, that will show the menu with those two options.
The number next to the tab title shows the total number of comments.

==== Items

On the second tab, you can update the list of content items in this issue.
There can be multiple items or no content at all.
Child/dependent items of the selected content can be toggled by clicking on the tree icon next to the content item.

If you are inside a *task* and click the `Publish...` button, you will be taken to the Publishing Wizard where you can publish items immediately
or schedule publishing.
For a _Publish Request_ you can publish items or schedule publish directly from this dialog.

The number next to the tab title shows the total number of content items inside the issue.

image::dialog-issue-edit-2.png[Issue content, 700]

==== Assignees

On the third tab, assignees can be added and removed from this issue. The number next to the tab title shows the total number of assignees.

image::dialog-issue-edit-3.png[Issue assignees, 700]

[[publish_requests]]
== Publish requests

A *publish request* asks another user to review and publish one or more content items.

[[create_a_publish_request]]
=== Create a publish request

The *Request publishing* action is available from the same places as <<../actions/publish#publish,Publish>> — the toolbar, the context menu, and the Content Editor — but it replaces the *Publish* button for users without publish permission.

TIP: When *Request publishing* is invoked on a single item that is currently *In progress*, the item is automatically marked *Ready for publishing*, on the assumption that requesting a publish signals the work is finished.

The Publish Request wizard has two steps.

*Step 1.* Review the items to be published together with their dependencies — the same tree the Publishing wizard would show.

image::request-publishing-wizard-1.png[Publish Request wizard — step 1, 660]

*Step 2.* Describe the changes (required) and pick one or more assignees who will receive the request.

image::request-publishing-wizard-2.png[Publish Request wizard — step 2, 671]

Clicking *Create request* creates the publish request and opens its detail dialog.

=== The publish request dialog

The publish request dialog looks much like an Issue dialog, with one important difference: the *Items* tab includes a *Publish now* button so a reviewer can publish directly from the dialog. The calendar icon at the bottom toggles a scheduling form to set online-from/online-to dates.

image::publishing-request-1.png[Publish request dialog, 673]
image::publishing-request-2.png[Publish request with scheduling, 673]

=== Find a publish request

Publish requests appear in the same <<#issues_list,*Open Issues*>> dialog as tasks, on a dedicated *Publish requests* tab.

image::publishing-request-list.png[Publish request list, 701]

When the currently-edited content is part of an open publish request, the default toolbar action in the Content Editor becomes *Open request* — clicking it jumps to the most recent open request containing the item.

image::publishing-request-toolbar.png[Open request toolbar button, 494]

The full list of open issues and publish requests containing this item is available from the dropdown next to the main button.

image::publish-button-menu.png[Issues and publish requests menu]

The same list is also shown in the Preview-panel toolbar in the <<../workbench/navigator#,Navigator>>.

image::issues-toolbar.png[Issues menu in the Preview toolbar]
