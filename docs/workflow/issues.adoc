= Issues
:toc: right
:imagesdir: images
:experimental:

Issues coordinate editorial work within a project. Content Studio supports two types:

* *General issues* track tasks such as checking an article or updating a set of authors. They can have assignees, comments, and optionally a selection of content items.
* *<<#publish_requests,Publish requests>>* ask another user to review and publish one or more content items. Content is mandatory. They include the controls needed to review the publishing batch and publish or schedule it.

Both types have an *Open* or *Closed* status. This status belongs to the issue: creating, assigning, or manually closing an issue does not change the attached content's <<../workflow#,workflow or publish state>>.

[[issues_list]]
== Issues list

Click *Open issues* in the Content Studio header to open the Issues dialog for the current project. The header shows the number of open issues; when there are none, it displays *No open issues*.

.Open the issues overview from the header, or create an issue from the toolbar menu
image::Issues-bar.png["Content Studio header with Open issues and the toolbar menu's Create issue action", 900]

The dialog lists general issues and publish requests together. Each row shows its number, title, creator, creation time, and status. A hash icon identifies a general issue; a globe identifies a publish request. Click a row to open its details, or btn:[New Issue] to create a general issue.

.General issues and publish requests in the same list
image::issues-list.png["Issues dialog listing two general issues and a publish request, with Open and Closed tabs and New Issue button", 900]

Use the *Open* and *Closed* tabs to choose the status, and the *Filter* selector to narrow the list:

* *All* — both issue types.
* *Assigned to Me* — issues assigned to the current user.
* *Created by Me* — issues created by the current user.
* *Publish requests* — requests for review and publishing.
* *Issues* — general editorial issues.

Counts show how many entries match each choice. Choices with no matching entries are disabled.

.Filtering by involvement or issue type
image::issues-filter.png["Issues filter showing All, Assigned to Me, Created by Me, Publish requests, and Issues", 900]

[[tasks]]
== General issues

A general issue describes work to be done. It can exist without attached content, and attaching an item does not mark it ready or publish it.

[[create_a_task]]
=== Create an issue

Use btn:[New Issue] in the Issues list or *Create issue* in the toolbar menu. When started from selected content, the selection is added to the new issue.

The *New Issue* dialog contains a required *Title*, an optional *Description*, and an *Assignees* selector. Choose one or more users to involve in the work, or leave the issue unassigned. Content can be linked to the issue through the *Items* selector.

.Creating a general issue and selecting assignees
image::issue-create.png["New Issue dialog with Title, Description, Assignees selector, and Create issue button", 900]

Click btn:[Create issue] to save the issue and open its details. You can update its content and assignments afterwards.

[[update_an_issue]]
== Issue details

The details dialog shows the title and issue number, a status selector, and tabs for comments, content, and assignees. Tab counts show the number of entries. Use btn:[Back to issues] to return to the list.

Click the title to edit it. Use the status selector to change an issue from *Open* to *Closed* when the work is complete, or reopen it if further work is needed. Closing preserves the issue and its discussion in the *Closed* list. Reopen a closed issue before changing its title, comments, content, or assignees.

=== Comments

The *Comments* tab holds the discussion, including the description or comment supplied when the issue was created. Enter text in the *Comment* field and click btn:[Comment] to post it. The menu beside a comment provides *Edit* and *Delete* when those actions are available to you.

.An issue's discussion and status selector
image::issue-view.png["Open issue with Comments, Items, and Assignees tabs, existing comments, and a Comment field", 900]

=== Items

For a general issue, the *Items* tab lists its attached content. Search or browse with the selector to add items. Click an item's name to open it in the Content Editor; use the remove control beside it to detach it from the issue. Removing an attachment does not delete the content.

.Content attached to a general issue
image::issue-items.png["Issue Items tab with a content selector and two attached authors, each with a remove control", 900]

Publish requests use a *Publish request* tab instead, with publishing states, dependencies, and publishing controls. See <<#_the_publish_request_dialog,The publish request dialog>>.

=== Assignees

The *Assignees* tab shows the users assigned to the issue. Search for users to add them, or use the remove control beside an assignee to remove their assignment. Multiple users can be assigned to the same issue.

.Managing the people assigned to an issue
image::issue-assignees.png["Issue Assignees tab with a user selector and an assigned user with a remove control", 900]

[[publish_requests]]
== Publish requests

A publish request hands content to another user for review and publishing. Use it when you lack publish permission, or when you want another person to review your changes before they go live. Creating the request does not publish the content.

A request wraps the <<../actions/publish#publishing_wizard,Publishing wizard>> in an issue, adding a title, assignees, discussion, and an Open/Closed status. The content selection, dependencies, readiness checks, validation, and publishing controls follow the same rules as the wizard.

A publish request must contain at least one content item. General issues can be created without content, but a publish request needs a publishing batch for the reviewer to act on.

[[create_a_publish_request]]
=== Create a publish request

Select one or more content items and choose *Request publishing* from the toolbar or context menu. For users without publish permission, it is the primary publishing action once content is ready.

.Request publishing from the toolbar menu
image::publish-request-action.png["Navigator with ready content selected and Request publishing in the toolbar menu", 1100]

The *Request publishing* dialog combines the request details and its content in one form. Enter a required *Title*, optionally *Add a comment*, and select assignees to review the request.

.Describing the request and choosing reviewers
image::publish-request-create.png["Request publishing dialog with readiness status, Title, Add a comment, Assignees, and Create request button", 900]

Review the *Items* and *Dependencies* further down in the same dialog. *Include child items* adds descendants where available, and the dependency checkboxes control which related items are included. Selection changes must be applied before continuing. See <<../actions/publish#_dependencies,Publishing dependencies>> for these shared controls.

.Reviewing the content included in the request
image::publish-request-items.png["Lower portion of Request publishing with selected content, Include child items, a dependency, and Create request button", 900]

The status bar reports readiness. Resolve any blocking conditions before submitting; see <<../actions/publish#mark_as_ready,Mark as ready>> and <<../actions/publish#_validation,Publishing validation>>. Click btn:[Create request] to create the request and open its details. For multiple included items, the button displays the item count.

=== The publish request dialog

A publish request opens on its *Publish request* tab, which presents the Publishing wizard's controls within the issue. It shows the current content states, included items and dependencies, and any conditions that block publishing. Use the content selector to add items, or adjust the existing selection and apply the changes.

.Reviewing and publishing an open request
image::publish-request-view.png["Publish request details with readiness status, content selector, selected content and dependency, Schedule, and Publish now", 900]

The *Comments* and *Assignees* tabs work as described under <<#update_an_issue,Issue details>>. Use comments to discuss changes or ask the author to revise the content before publishing.

A reviewer with publish permission can use btn:[Publish now] to publish the included changes, or btn:[Schedule] to set publishing dates. The same <<../actions/publish#_validation,validation>> and <<../actions/publish#scheduled_publishing,scheduling rules>> apply as in the Publishing wizard. After a successful publishing operation, the request is closed automatically.

=== Find a publish request

Open the <<#issues_list,Issues list>> and select the *Publish requests* filter. Use *Open* to find requests awaiting work, or *Closed* to find completed requests and their discussions. Closing a request manually does not publish its content.
