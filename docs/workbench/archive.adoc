= Archive
:toc: right
:imagesdir: images

The *Archive* is a separate storage area where deleted content is held before it is permanently removed.

NOTE: Archiving is available in all Content Studio installations: the *Delete* action moves content to the Archive. The dedicated Archive browser—including browsing, restoring, and permanently deleting archived content—requires a https://market.enonic.com/vendors/enonic/content-studio-plus[Content Studio+] subscription.

== Introduction
The Archive preserves the structure of removed items (descendants, attachments, version history) so content can easily be restored if it is deleted by mistake.

When a user performs the <<../actions/delete#,Delete>> action from the Navigator or Editor, the item is moved to the Archive. From the Archive, items can be *Restored* to their original location when possible, or to the project root when the original location is unavailable. They can also be permanently deleted.

== Archive browser

image::archive-browse.png[View of the archive browser with list, preview and details panel, 1440px]

Click the *Archive* icon in the Content Studio main menu to open the Archive view. It is similar to the <<navigator#,Navigator>> with a few differences:

* Only two actions are available: *Restore* and *Delete*. *Restore* returns the selected content to its original location when possible, falling back to the project root when necessary. *Delete* permanently removes the selected content from storage.
* Preview only works for media items (images, videos, etc.).
* The widget selector has only two choices: *Details* and *Version history*.

The preview panel on the right shows who archived each item, when, and the original location of the item.

== Restore

NOTE: Archived content can only be restored from the Archive view, which requires https://market.enonic.com/vendors/enonic/content-studio-plus[Content Studio+].

The *Restore* action in the Archive view opens the *Restore from Archive* dialog. Content is always restored together with all of its descendants, preserving structure. Content returns to its original location when that location is available; otherwise, it is restored to the project root.

If an item is restored directly from a layer's Archive, it becomes local and is no longer linked to the corresponding content in the parent layer.

image::archive-restore.png[Restore dialog showing the items that will be restored, 912px]

TIP: If an item with the same path already exists at the restore location, the system appends `-1`, `-2`, etc. to the restored item's path.

== Permanent deletion

The *Delete* action in the Archive view permanently removes the selected items from the Archive. This is a separate operation from the <<../actions/delete#,Delete>> action in the Navigator and Editor, which only moves content into the Archive.

image::archive-delete.png[Permanently delete dialog, 912px]

Select one or more items and click *Delete* to open the *Delete from Archive* dialog. The dialog lists:

* The items selected for deletion.
* Any descendants and other content items that will be deleted with them.
* The total number of affected items on the confirmation button.

Deleting a parent item also deletes all of its descendants. Review the complete list before confirming the operation.

IMPORTANT: Permanent deletion removes the archived content, its attachments, and its stored version history. It cannot be undone or restored through Content Studio. Recovery requires an applicable repository snapshot or backup and must be performed outside Content Studio by an administrator.

Permanent deletion applies to the current project or layer. In a layered project, inherited content may reappear after its archived copy is permanently deleted; see <<archive_layers,Archive and layers>>.

== Version history
Delete and restore operations will appear as entries in the version history for the content item, making it possible to see when the item was archived and restored, and by whom.

== Archive and layers

Archive operations in <<../projects/layering#,layers>> follow the content inheritance model:

* Archiving an item in a parent layer also archives corresponding items in descendants that still inherit both their *Content* and *Parent* dimensions. A descendant remains active if either dimension is local or if inbound references from outside the archived selection prevent it from being archived.
* Archiving an inherited item directly in a child layer does not affect the parent. The archived copy becomes local and stops receiving inherited changes.
* A new layer inherits the archive state of its parent. Content already archived in the parent is therefore also archived in the new child layer.
* Permanently deleting inherited content from a layer's Archive can cause synchronization to create a fresh inherited copy if the item still exists in the parent layer.
+
NOTE: When permanently deleting a localized item, these changes will be lost and cannot be recovered, even if the item is recreated from the parent layer.

See <<../projects/layering#archive_and_delete,Archive and delete>> for the relationship between Archive operations and inheritance.
