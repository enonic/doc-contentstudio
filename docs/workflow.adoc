= Workflow
:toc: right
:imagesdir: images

Workflow is the state machine a content item moves through on its way to being published. 

== Workflow state
The general workflow state is presented as an icon next to the content-type throughout the UI (a red icon indicates the content is invalid — for example, required fields are missing).


Workflow state icons:

image::workflow-state.png[List of workflow state icons red (x) invalid - yellow (!) in progress - green (✓) ready, 565px]

* *<<#_invalid,Invalid>>* — if a mandatory field is missing, or a validation test fails.
* *<<#_in_progress,In progress>>* — default state for a new or modified content item. Cannot be published.
* *<<#_ready_for_publishing,Ready for publishing>>* — the editor has explicitly flagged the content as done.

When an item has been published, the workflow state is no longer displayed - as there are no changes to publishing. If a published item is modified, it immediately reverts back to *In progress*.


Transitions between the states are driven by four actions: *Mark as ready*, *<<actions/publish#,Publish>>*, *<<actions/unpublish#,Unpublish>>*, and general creation and editing.


[[_invalid]]
=== Invalid (blocking publishing)

Set whenever the content fails validation. Invalid content is marked with a red icon, and invalidity *takes priority over the other state icons* — an invalid item is shown as invalid whether it is in progress or ready.

Typical causes:

* a required field is empty — including the display name
* an input has fewer or more entries than its allowed number of occurrences
* a value fails the validation of its input type — a regular expression on a text line, a malformed rich text field, an invalid attachment
* a required field is missing in a mixin, or in the app configuration of a site
* a custom validator on the server rejects the content

Validation runs when the content is opened and re-runs continuously while editing, so the state updates as the form is filled in. Invalid inputs are highlighted where they occur, and the errors are also summarized at the top of the form, so problems inside collapsed or nested sets are not missed. In the Content Editor, the state icon sits next to the *Publish* button in the toolbar.

Invalid content can still be *saved* — validity never blocks saving work in progress. What it blocks is progress through the workflow:

* *Mark as ready* is disabled for invalid content — an invalid item cannot reach <<#_ready_for_publishing,Ready>>, and therefore cannot be published the normal way.
* In the <<actions/publish#,Publishing wizard>> invalid items block the batch, just like in-progress items do, but the bulk *Mark as ready* link will not clear them. They must either be fixed or excluded from the batch.

Editing a published item into an invalid state is allowed: the red icon appears for the `draft` version, while the version already live on `master` is untouched.

NOTE: Validity is not a stored state — unlike *In progress* and *Ready* it is derived, by validating the content every time it is loaded or changed.



[[_in_progress]]
=== In progress (blocking publishing)

The default state of a new content item. Signals that the content is being worked on; it will stay in this state until the editor explicitly marks it as ready, or until a publisher overrides and publishes it directly.

`In-progress` state *blocks publishing* — this is deliberate, to keep unfinished content from being published by accident. Whenever a batch contains at least one in-progress item, the <<actions/publish#,Publishing wizard>> disables *Publish*, shows a warning, and pins the offending items to the top of the list:

image::workflow-in-progress.png[In-progress content is blocked in the Publishing wizard, 913px]

There are three ways to resolve this from inside the dialog:

* *Mark all as ready at once* — click the *Mark as ready* link in the warning at the top of the dialog. Every in-progress item in the batch is marked ready in one operation, the warning clears, and *Publish* becomes enabled.
* *Handle items one at a time* — click an item's link in the list to open it in the Content Editor, finish the work, and mark it ready there. Validation re-runs when the wizard is updated, so the item drops off the warning list as soon as it is ready.
* *Remove items from the batch* — Exclude the item by clicking the *Remove* link, or unchecking it in the dependency list. The warning clears when no in-progress items remain, and *Publish* becomes enabled.


NOTE: The bulk *Mark as ready* link can be disabled in the <<config#disable_mark_as_ready,Content Studio configuration>>. With bulk readiness disabled, each item must be opened and marked ready individually — useful when a stricter approval process is required.

The default toolbar action for in-progress content is *Mark as ready*.

[[_ready_for_publishing]]
=== Ready (for publishing)

Set by the *Mark as ready* action from the Content Editor or Content Navigator. The yellow `!` icon is replaced with a green `✓`, and the item becomes eligible for publishing.

The default toolbar action changes to *<<actions/publish#,Publish>>* (if the user has publish permission) or *<<issues/publish-request#,Request publishing>>* (if not).

TIP: Editors with publish permission may still use *Request publishing* when content needs sign-off or additional input from another user.

Any edit to a *Ready for publishing* item immediately resets it to *In progress* — the editor must mark it ready again once the edits are finished.


[[_publish_request]]
== Publish request

Publish requests are part of the effective workflow, but are not a workflow state by itself, as they operate across multiple items.

Items can be added to issues, or publish requests to aid the communication between users, or in the case where a user does not have publish permissions. The full wizard, the request dialog, and how requests are managed are documented on the <<issues/publish-request#,Publish request>> page.


== Publish state

In addition to the workflow state, the UI displays the publishing state of each content item. This is shown as a text element in the second column of the content list, and in the Content Editor toolbar.

There are four publishing states:

image::workflow-publish-state.png[Publishing state is listed in the priority two column, here all items are online (aka published), 565px]

=== Offline (not published)

The default state of a new content item. Signals that the content is not published, and will not be visible on the website. <<actions/unpublish#, Unpublishing>> an item returns it to this state as well.


[[_published]]
=== Online (published)

Set when the active version has been pushed from `draft` to `master`. No icon is shown — published is the default, quiet state.

Editing a published item resets the workflow state to *In progress*; 

NOTE: The `master` branch is unaffected by your edits in the `draft` branch until the item is published again.

[[_scheduled]]
=== Scheduled (not published yet)

When the editor has set a future date and time for the content to be published, the item is in the *Scheduled* state.

[[_expired]]
=== Expired (previously published)

When the editor has set a future date and time for the content to be unpublished, and this time is reached, the item enters the *Expired* state.
